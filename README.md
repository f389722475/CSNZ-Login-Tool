# CSNZ 桌面登录器 1.1.2-local1

**简体中文** | [English](README.en.md)

独立 Windows x86 / .NET 8 WPF 桌面程序。

## 注意：discord的#update频道，smilex更换了游戏版本，所以遇到启动器无法启动的原因是因为版本不匹配，启动器本身只支持0930版本的csnz，如果你使用的是0722版本，需要你自行修改源码适配其他版本，游戏版本问题不要来找我。

## 使用

右上角服务器地址左侧的 **CN / EN** 按钮可立即切换简体中文 / English，当前语言以紫色标示，选择自动保存。覆盖登录、注册、武器模组、插件、设置、帮助、确认对话框、服务端状态及错误反馈。系统文件夹选择窗口的通用按钮仍遵循 Windows 的显示语言。

运行 `dist/CSNZ_Launcher_1.1.2-local1/CSNZ登录器.exe`。原生补丁及许可证已内嵌，单独复制此 EXE 也能使用，不再依赖旁边的 `Native` 文件夹。

本仓库提供最新登录器源码、完整 C++ 原生组件及自编译武器 DLL；不包含 Skill、私人设计文档、账号数据、游戏 NAR 资源或内嵌这些资源的本地 EXE/ZIP。下述独立 EXE 使用说明针对自行准备匹配资源后生成的本地构建，不表示本仓库附带可直接下载的新版完整运行包。原生武器组件释放到 `%LOCALAPPDATA%\CSNZLauncher\Native\Weapons\版本-内容标识`，缓存不匹配时拒绝覆盖。核心日志在其中的 `shared/logs`。旧版客户端马神 0.7.4 已从当前源码树和内嵌交付移除，仅保留外部本地回退备份。

不再写死游戏目录。将 EXE 放在游戏根目录（包含 `Bin`）或 `Bin` 中，会按 EXE 所在位置识别，不依赖启动时的工作目录。移动到另一份完整游戏目录时优先使用相邻游戏；明确手动选择的外部目录仍会保留。如果找不到游戏，在「启动设置」选择根目录，也接受 `Bin` 或 `Bin/CSOLauncher.exe` 路径。不会改写原游戏 EXE/DLL 或启动脚本。启用原生武器时，首次准备会先询问，再备份并更新已知的资源覆盖包和专用服务端配置；未知自定义资源拒绝覆盖。

* 本机 / 开服模式且开启自动启动时，打开登录器会自动启动 `游戏目录/Server/CSNZ_Server.exe`，后台运行，不弹控制台。
* 右上角：红点 `Stop`、旋转指示 `Starting`、绿点 `Ready`；安全停止期间显示 `Stoping` 与旋转指示，退出后才显示 `Stop`。就绪以真实 CSNZ 协议横幅响应为准，不仅检查进程存在。
* 已有服务端会复用，登录器不取得其所有权，也不会停止它。
* 安全停止向 CSOHLDS 独占的隐藏 Windows 控制台写入 `quit` 输入事件，再向大厅发送 `shutdown`；不再把 CSOHLDS 命令写入它不读取的 stdin 管道。等待正常退出，超时不会强杀；不停止非本登录器启动的服务端。游戏运行时禁用停止行为，停服前会提醒其他玩家也将断线。
* 关闭登录器时可选择同时安全停止它自己启动的服务端；也可保留服务端。游戏运行时不会被登录器结束。
* 自动登录由内嵌的 `CSNZLauncherBridge.dll` 完成，独立于武器模组开关。它在游戏原登录回调中，通过原有游戏连接发送标准 `/login` 认证包，不再依赖可能丢弃命令的聊天 UI。服务端仍正常验证密码；错误密码会被拒绝。保留 `-disableauthui`，不重复要求输入账号密码；新账号首次创建角色仍在游戏内完成。不会预先另开会话登录账号，不重复发放登录奖励或改写数据库。
* 自动登录组件严格核对当前 `CSOLauncher.exe` 和 `hw.dll` SHA-256，并在运行时核对 PE、函数入口及当前两参数 ABI。未知版本拒绝启动，不覆盖原游戏二进制。组件内嵌于 EXE，释放到 `%LOCALAPPDATA%\CSNZLauncher\Native\LauncherAuth\1.0.0-package2`。
* 注册通过选定服务端的真实网络协议提交，只有明确的成功回复才显示成功。重复账号、格式错误、注册 IP 上限、数据库错误有单独提示，不直接读写用户数据库。
* 账号 5–15 位英文字母或数字；密码 5–15 位可见 ASCII 字符，不支持空格、双引号、反斜杠；注册密码不能全部为数字。这是当前服务端认证命令的字段约束。
* 记住账号、记住密码、显示/隐藏密码、密码二次确认、清除保存凭据、服务端地址/端口/TLS、启动后最小化均可用。
* 「武器模组」现在提供 12 个修复模块，默认勾选；未改动的 Arbalest 参照物已从列表和运行包移除。选择保存到下次启动，不热切换；显示分别区分“已选择”“等待地图”和实际运行数量。旧 LEGuard 不能同时运行。

## 原生武器加载

- Giga Break / LE、Lycaon、Brionac 三变体、Space Arbalest、Gravity / Abyss Repulsor、Naberius / Arcane Naberius、Frost Viper 均已迁移到 C++。Space Arbalest 保留，参照物 Arbalest 不在运行包内。
- 登录器只向它新建的本地 `CSOHLDS.exe` 加载武器模块，先完成校验和挂接，再启动客户端；不会向客户端或未知既有服务端注入武器逻辑。加入模式会自动跳过本地服务端及武器注入，保留本机开服时的勾选偏好，由远端开服者管理实际武器功能。
- 首次准备需关闭游戏和服务端。确认后，备份到游戏目录的 `CSNZLauncherBackups`，将 `Room.HostConnectingMethod` 改为 1 并保留其他配置，更新已知的 `Data/fixtrike.nar`。未知自定义包会拒绝覆盖；账户数据库、背包和原始二进制不改动。
- 默认专用服务端 UDP 端口 27015，可在设置页的“对局 UDP 端口”中调整。修改武器选择前先正常退出游戏并点击安全停止。
- 原生模块采用“12 个命名入口 DLL + 1 个共享核心”，不是 12 份重复挂钩。详情及离线构建见 `weapon-mods/README.md`。

## 局域网与互联网联机

设置页新增四种方式：本机、局域网 / VPN 开服、互联网开服、加入其他人的服务器。

- **开服者**：大厅连接地址仍用 `127.0.0.1`，大厅 TCP 端口须与 `ServerConfig.json` 一致。局域网 / VPN 模式将可被玩家访问的本机 IPv4 填入“向玩家通告的对局 IPv4”；“查看本机 IPv4”会列出网卡，多网卡不擅自猜选。互联网模式填公网 IPv4。
- **玩家**：选择“加入其他人的服务器”，大厅填开服者提供的地址、端口及 TLS 设置。无需取消所有武器勾选；不启动自己的大厅 / CSOHLDS，也不会加载客户端武器 DLL。首次只准备已知版本的本机资源，不要求本地 `Server` 目录或修改本地服务端配置。
- **端口**：默认大厅 `TCP 30002`，对局 `UDP 27015`。放行防火墙；公网路由器必须把这两个端口以相同端口号转发到开服电脑。没有公网 IPv4 / 位于 CGNAT 时，使用能互通的 VPN 地址。公网模式下本机和同局域网玩家还需要路由器支持 NAT 回环，否则统一改用 VPN。程序不修改防火墙或路由器，不自动开 UPnP。
- “复制联机信息”使用已保存配置，不包含账号密码，也不会把“已复制”当作外网已经连通。当前协议只接受对局 IPv4；`-hostdomain` 尚未被大厅实现，不能用域名代替这个字段。
- 更改网络方式、通告地址、端口或游戏目录前，先安全停止已有服务端。TLS 必须与大厅 SSL 配置一致；CSOHLDS 同步使用 `-usessl`，不会关闭证书检查来掩盖配置错误。

实现按当前本机服务端协议核对：`HostServer/AddServer`（81/0）上传 UDP 端口和 `-hostip`；大厅在 `HostServerJoin` 中原样发给玩家。大厅登录地址不是对局通告地址，这两个字段现在分开处理。

## Plugins / Class Awakening

侧栏 Plugins 位于 Weapon Mods 与 Settings 之间，使用相同的卡片与文字排版。勾选后自动加载本地 C++ 原生觉醒插件，底部显示真实的“已加载 X 个插件”；中英文同步切换。

- 补齐已拥有角色的 20 个合法槽位，修复材料扣除、词条消耗与提取返还、保护替换、交换和属性重置。
- 服务端 x64、游戏只读配对诊断 x86，均由内嵌原生加载工具处理，不依赖 Python / Frida。只匹配已验证的 CSNZ0930 构建。
- 首次启用前在线备份到游戏的 `Server/AwakeningBackups`。停用不会回收槽位或清空已有词条；原 DLL 安全地保留到进程退出。
- 内嵌组件释放到 `%LOCALAPPDATA%\CSNZLauncher\Native\ClassAwakening\0.3.0-native-r1`，不覆盖原游戏二进制或资源包。旧 Python/Frida 修复服务不能并行运行。
- 转移功能没有客户端配置，仍不支持；没有把单一配对武器的验证扩展成全部武器或远端联机通过。
- 悬停异常状态文字可查看诊断；“已勾选”不等于“已加载”。关闭修复后原版交易缺陷会重新出现。


## 密码与网络边界

配置存于 `%LOCALAPPDATA%\CSNZLauncher\settings.json`。账号与偏好可读；密码仅在勾选记住密码时保存为 **Windows DPAPI 当前用户加密**的密文，绑定服务器地址、端口、TLS 模式和账号。更换服务器会清空输入和旧凭据，取消记住密码会移除密文字段内容。

自动登录账号、密码**不再出现在游戏命令行**。登录器将凭据临时传给自己新启动的游戏进程，认证请求发出后清空组件内的副本；不写明文文件或日志。同一 Windows 用户或管理员仍可能读取进程内存，DPAPI 不等于对管理员保密。原启动器 stdout/stderr 被丢弃而不保存。

远程非 TLS 登录与注册均必须先明确确认未加密传输风险；默认协议调用仍拒绝远程明文注册，只有用户确认后 UI 才允许。建议使用可信局域网、加密 VPN 或 TLS。启用 TLS 的外置注册仍要求证书/域名通过系统校验，没有接受任意证书的后门。服务器 TLS 与登录器设置必须一致。`ready` 表示 CSNZ 横幅响应，不代表账号已认证或 TLS 证书已验证。

服务端没有邮件/短信找回密码接口，因此「忘记密码」明确指向管理员，不假装发送找回邮件，也不绕过账号验证。

## 构建

### GitHub 源码与本地资源边界

GitHub 版本包含 `src/CSNZ.Launcher`、`native-launcher-source`、`native-awakening-source` 和 `weapon-mods` 的完整源码、第三方依赖与许可证。`weapon-mods` 可独立运行 `build-native.cmd` 和 `build-tests.cmd`，普通武器构建不需要游戏资源。

完整登录器目前必须内嵌已准备的 `weapon-mods/local-assets/fixtrike.nar`，该资源不随仓库提供。从公开仓库克隆后，先自行合法准备与 `weapon-mods/asset-manifest.json` 匹配的本地资源，再运行下述登录器构建。缺少资源时 `build.ps1` 明确拒绝；尚未提供自动从使用者安装提取/重建资源的公开流程，请勿创建空文件、取消校验或使用来源不明的资源包。含游戏资源的本地运行包、源码 ZIP 和 `dist` 不上传 GitHub，`package.ps1` 的公开资源打包禁令保留。

### 完整本地交付

完整本地源码目录为 `dist/CSNZ_Launcher_1.1.2-local1_Source/`，另有同名 `_Source.zip`。包含 `src/CSNZ.Launcher` 的 C#/XAML、自动登录桥、原生觉醒、全部武器组件源码及完整构建依赖；源码入口说明见 `src/README.md`。仅生成源码交付：`pwsh -NoProfile -File .\package.ps1 -LocalOnly -SourceOnly`，不会生成部署包或覆盖已有源码交付。此包含重建当前本地版本所需的游戏资源，不可据此公开再分发。

需要 .NET 8 SDK；内嵌原生组件随源码包提供，如使用 `-RebuildNative` 重新编译，还需要 Visual Studio 2022 C++ x86/x64 Build Tools。

    pwsh -NoProfile -File .\build.ps1

输出独立运行的 `dist/CSNZ_Launcher_1.1.2-local1` 目录。运行时默认不要求管理员权限。新登录器源码在 `src/CSNZ.Launcher`；定向测试在 `tests/Launcher.Smoke`（测试明确要求隔离服务端目录，不允许使用正式数据库）。

所有武器源码和自编译 DLL 统一收在 `weapon-mods`，按武器名称分目录；公共家族逻辑和 MinHook 在 `weapon-mods/shared`。旧 `native-mod-source` 已迁入外部回退备份。自动登录源码仍在 `native-launcher-source`，角色觉醒仍在 `native-awakening-source`。GitHub 同步仅包含已审查的工程文件，`.nar`、本地运行包、数据库和私人配置被排除。正常运行不依赖 Python/Frida。

## 协议依据

外置注册是独立实现的小型客户端，仅使用公开线上字段格式，没有复制服务端的账号数据库或密码处理代码。核对的上游版本：

* [JusicP/CSNZ_Server](https://github.com/JusicP/CSNZ_Server/tree/6e5275cb4bf4178b391a1db09dd604c8eaa1420b)：`src/net/tcpserver.cpp`（连接横幅先于 TLS）、`src/net/sendpacket.cpp`（4 字节头）、`src/manager/usermanager.cpp`（版本与注册条件）、`src/manager/channelmanager.cpp`（注册请求及结果）、`src/servercommands.h`（正常停服）。
* [JusicP/Launcher_CSNZ](https://github.com/JusicP/Launcher_CSNZ/tree/9b1872aa32b748a1fb95e129807f50008057318b)：`hook.cpp` 中的旧自动登录调用仅作为故障分析依据；1.0.6 不再通过命令行传递凭据。
* 本机 `Server/Documentation/Client Launcher Info.txt` 与 `Server/ChangeLog.txt`，版本 `30.09.2026_EoS`。旧 `-register` 参数已经删除，没有使用该失效入口。

协议：原始 ASCII 横幅 `~SERVERCONNECTED\n` → 可选 TLS 握手 → `0x55 | seq:u8 | bodyLen:u16LE | body`。先发版本包（启动器版本 67 / 游戏版本 26 / 当前 client.dll 时间戳），收到版本成功后发送 UMsg 67、LobbyChat 1、NUL 终止的 `/register` 命令，等待 UMsg 67 / MsgBox 10 中的明确注册结果。接收会处理 TCP 分片与长度上限，未知/超时回复不算成功。
